# GearBy 사용자 흐름

상태: active / normative / current
상위 문서: [`docs/SPEC.md`](../SPEC.md)
선행 문서: [`01.prd.md`](./01.prd.md), [`02.functional-spec.md`](./02.functional-spec.md)

이 문서는 상위 제품·기능 요구사항을 사용자 행동과 예외 흐름으로 상세화하는 Source of Truth다. 새로운 기능이나 범위를 독립적으로 추가하지 않는다.

## 1. 역할과 채널

| 역할 | 채널 | 범위 |
| --- | --- | --- |
| 사용자 | 모바일·데스크톱 웹 | P0 매장 탐색·피드백, P1 장비군 가이드 |
| 관리자 | 데스크톱 웹 | 매장·분류·보정 룰·피드백 검수 |

## 2. FLOW-CUR-010 매장 발견 기본 흐름

1. 사용자가 홈의 지도·목록 화면에 진입한다.
2. 서비스가 공개 상태의 매장과 활동 카테고리를 조회한다.
3. 사용자가 하나 이상의 카테고리, 검색어, 지도 영역 또는 위치 조건을 선택한다. 복수 카테고리는 OR 방식으로 적용한다.
4. 서비스가 지도 마커와 목록에 같은 매장 집합을 표시한다.
5. 사용자가 지도 마커 또는 목록 항목을 선택한다.
6. 서비스가 같은 매장 상세를 표시한다.
7. 사용자가 전화 또는 NAVER 길찾기를 선택한다.
8. 서비스가 외부 동작임을 알리고 해당 경로로 연결한다.

**완료 조건:** 사용자가 검수된 매장을 발견하고 상세 또는 외부 길찾기로 이동한다.

### 검색어 보정 분기

1. 사용자가 오타나 동의어가 포함된 검색어를 입력한다.
2. 승인된 보정 룰이 있으면 서비스가 원 검색어와 적용 검색어를 표시한다.
3. 서비스가 보정 결과를 기본으로 표시한다.
4. 사용자가 원 검색어 결과 보기를 선택하면 서비스가 보정을 끄고 원 검색어로 다시 조회한다.
5. 승인된 룰이 없으면 서비스가 원 검색어로 검색한다.

### 지도 영역 검색 분기

1. 사용자가 지도를 이동하거나 확대·축소한다.
2. 서비스는 자동으로 검색하지 않고 `이 지역 검색`을 표시한다.
3. 사용자가 버튼을 선택하면 현재 지도 영역의 `bbox`로 지도와 목록을 함께 갱신한다.

### 위치 권한 거부 분기

1. 사용자가 위치 권한을 거부한다.
2. 서비스는 이름순·지도 영역 기반 탐색을 유지한다.
3. 현재 위치가 필요하다는 이유만으로 전체 매장 탐색을 막지 않는다.

### 결과 없음 분기

1. 조건에 맞는 공개 매장이 없다.
2. 서비스는 임의 매장을 만들지 않고 빈 결과를 표시한다.
3. 사용자는 조건 초기화 또는 신규 매장 제보로 이동할 수 있다.

### 정보 재검증 필요 분기

1. 공개 매장의 재검증 주기가 지난다.
2. 서비스는 매장을 즉시 숨기지 않고 `REVIEW_DUE`와 마지막 검증 시각을 표시한다.
3. 사용자는 정정 피드백을 제출할 수 있고 관리자는 재검수 대기열에서 처리한다.

## 3. FLOW-REC-010 장비군 가이드 기본 흐름 (P1 planned)

1. 사용자가 장비 가이드 진입점을 선택한다.
2. 서비스가 `RecommendationSession`을 생성한다.
3. 사용자가 활동, 경험 수준, 기간, 계절, 인원, 이동수단을 입력한다.
4. 사용자가 예산·무게·편의·내구성 선호와 필수 제약을 확인한다.
5. 서비스가 입력 유효성을 검증하고 프로필을 저장한다.
6. 서비스가 장비군, 스타터 키트 여부, 선정 이유, 경고, 미충족 제약을 표시한다.
7. 사용자가 특정 장비군의 검증 매장 보기를 선택한다.
8. 서비스가 검증 상태가 유효하고 만료되지 않은 매장 연결만 표시한다.
9. 사용자는 매장 상세·지도 탐색으로 이동하거나 추천 피드백을 남긴다.

**완료 조건:** 사용자가 설명 가능한 장비군 가이드를 확인하고, 필요하면 검증 매장 탐색으로 연결된다.

### 입력 오류 분기

1. 필수 프로필 값이 누락되거나 유효 범위를 벗어난다.
2. 서비스가 해당 항목과 수정 방법을 한국어로 표시한다.
3. 사용자가 입력을 수정한 뒤 동일 세션에서 다시 제출한다.

### 가이드 근거 부족 분기

1. 현재 규칙으로 신뢰할 수 있는 장비군을 구성할 수 없다.
2. 서비스가 임의 추천 대신 빈 결과와 부족한 입력·미충족 제약을 표시한다.
3. 사용자는 프로필을 수정하거나 매장 탐색으로 이동한다.

### 검증 매장 없음 분기

1. 장비군 가이드는 존재하지만 유효한 매장 근거가 없다.
2. 서비스는 `재고 없음`이라고 단정하지 않고 `검증된 매장 정보 없음`을 표시한다.
3. 사용자는 일반 지도 탐색 또는 신규 매장 제보로 이동한다.

## 4. FLOW-FDB-010 정정·피드백 흐름

1. 로그인하지 않은 사용자가 매장 상세 또는 공통 피드백 진입점을 선택한다.
2. 사용자가 정정, 일반 의견, 신규 매장 중 유형을 선택한다.
3. 사용자가 내용을 입력하고 선택적으로 회신 이메일과 연락 동의를 제공한다.
4. 서비스가 유효성을 검사하고 접수 ID와 `ACCEPTED` 상태를 반환한다.
5. 관리자가 피드백을 검토해 해결 또는 반려하고 처리 요약을 기록한다.
6. 연락 동의와 이메일이 모두 있을 때만 후속 알림을 처리한다.

## 5. FLOW-OPS-010 관리자 매장 운영 흐름

1. 배포 환경에 설정된 관리자 계정의 인증 세션이 `ADMIN` 권한을 가지면 서비스가 관리자 진입점을 표시한다.
2. 관리자가 관리자 진입점을 통해 대시보드에 진입한다.
3. 서비스가 서버 세션과 `ADMIN` 권한을 다시 검증한다.
4. 관리자가 매장 상태, 카테고리, 검수 플래그 또는 피드백 현황을 확인한다.
5. 신규 매장을 `DRAFT`로 등록하거나 기존 매장을 수정한다.
6. 관리자가 매장을 `IN_REVIEW`로 제출한다.
7. 검수 결과에 따라 `PUBLISHED` 또는 `REJECTED`로 전환한다.
8. 공개된 매장만 사용자 검색과 지도에 노출된다.
9. 이후 정정은 다시 검수 흐름을 거쳐 공개 데이터에 적용한다.

### 관리자 접근 거부 분기

1. 인증되지 않았거나 `ADMIN` 권한이 없는 사용자는 관리자 진입점을 볼 수 없다.
2. 사용자가 관리자 URL을 직접 요청하면 서비스는 로그인 또는 접근 거부 상태를 표시하고 운영 데이터를 요청하지 않는다.
3. 관리자 API는 토큰이 없으면 `401`, 권한이 부족하면 `403`을 반환한다.

### 외부 매장 후보 수집 분기

1. 승인된 배치 작업이 PoC를 통과한 크롤링 또는 NAVER 관련 API 채널에서 대한민국 전역의 매장 후보를 수집한다.
2. 서비스가 출처와 수집 시각을 기록하고 기존 매장과 중복 가능성을 계산한다.
3. 신규·변경 후보를 공개하지 않은 상태로 관리자 검수 대기열에 등록한다.
4. 관리자가 출처, 중복 여부, 주소, 좌표와 카테고리를 검수한다.
5. 승인된 후보만 기존 매장 수명주기를 거쳐 `PUBLISHED`된다.

### 검색 보정 운영 분기

1. 관리자가 검색 보정 룰과 실제 적용 결과를 조회한다.
2. 잘못된 룰을 수정·비활성화하거나 새 룰을 등록한다.
3. 변경 이후의 사용자 검색에만 승인된 룰을 적용한다.

### 카테고리 검수 분기

1. 시스템 또는 관리자가 분류 오류 가능성 플래그를 만든다.
2. 관리자가 담당자와 검수 결과를 기록한다.
3. 수정이 필요한 매장은 공개 상태를 직접 덮어쓰지 않고 수정·검수 흐름을 따른다.
