## 1. 제품 정의

GearBy는 한국의 아웃도어 사용자가 다음 두 가지 작업을 한 서비스 안에서 수행하도록 돕는다.

1. 검수된 오프라인 아웃도어 매장을 지도에서 발견한다.
2. 활동과 일정, 경험 수준, 선호에 맞는 장비군을 설명과 함께 안내받는다.

지역 기반 매장 탐색을 최초 MVP인 P0로 제공하고, 현재 제품 방향인 장비군 가이드는 P0 출시 이후 P1로 추가한다.

## 2. 해결할 문제

### CUR-010 매장 발견 문제
- 사용자는 일반 지도, 커뮤니티, SNS를 오가며 활동에 맞는 전문 매장을 찾아야 한다.
- 매장명·카테고리 표현 차이와 오타 때문에 적절한 결과를 놓칠 수 있다.
- 주소, 영업시간, 연락처, 취급 활동 등의 정보가 오래되었는지 판단하기 어렵다.

### REC-010 장비 선택 문제
- 입문자는 활동에 필요한 장비군과 선택 기준을 알기 어렵다.
- 백패킹, BPL/UL, 오토캠핑, 에어텐트 캠핑, 장거리 하이킹, 짧은 입문 산행은 필요한 장비와 우선순위가 다르다.
- 특정 제품을 바로 추천하면 가격·재고·안전성 근거가 부족한 상태에서 과도한 확신을 줄 수 있다.

## 3. 대상 사용자

| 사용자군 | 주요 요구 |
| --- | --- |
| 백패킹 입문자 | 필수 장비군, 계절·숙박일수별 준비, 과도한 경량화 방지 |
| BPL/UL 지향 사용자 | 무게 민감도와 편의·안전 간 절충 설명 |
| 오토캠핑 사용자 | 차량 이동, 인원수, 대형·에어텐트 설치 난이도와 부피 고려 |
| 등산 입문자 | 짧은 산행에 필요한 최소 장비와 기상·안전 경고 |
| 장거리 하이커 | 거리, 기간, 보급, 내구성, 중량을 반영한 장비군 구성 |
| 오프라인 매장 탐색 사용자 | 위치·카테고리·검색어 기반 전문 매장 발견과 길찾기 |
| 운영자 | 매장 정보, 분류, 검색 보정, 피드백을 검수하고 최신성을 유지 |

## 4. 제품 범위

### P0 first MVP — 지도 기반 매장 큐레이션
- 대한민국 전역의 검수된 아웃도어 매장을 대상으로 하는 지도·목록 탐색
- 등산, 백패킹, 캠핑, 클라이밍 카테고리 복수 선택 필터
- 매장명·카테고리 검색 및 제한된 오타·동의어 보정
- 크롤링과 NAVER 지도·검색 관련 API의 사용 가능성을 PoC로 검증하고, 허용된 채널에서 배치 수집한 매장 후보를 검수 후 공개
- 매장 상세, 전화, NAVER 길찾기 연결
- 매장 정보 정정·신규 등록 피드백
- `ADMIN` 권한 전용 매장 수명주기, 분류, 보정 룰, 피드백 관리
- 지도와 동등한 목록 탐색 경로

전국 범위는 서비스 가능한 지리적 경계를 뜻하며 전국 모든 매장의 완전한 보유를 보장하지 않는다. 검수되어 공개된 데이터만 사용자에게 제공한다.

### P1 planned — 활동·프로필 기반 장비군 가이드
- 활동, 경험 수준, 기간, 계절, 인원, 이동수단 입력
- 고정 enum에 가두지 않는 검증 가능한 문자열과 확장 컨텍스트 입력
- 예산, 무게, 설치 편의, 내구성 등의 선호와 필수 제약 입력
- 결정적인 규칙 기반 장비군 또는 스타터 키트 구성
- API 응답에 규칙 버전을 포함하고 사용자 화면에는 추천 이유, 경고, 미충족 제약만 표시
- 근거가 검증되고 만료되지 않은 매장 연결
- 추천 결과에 대한 유용성 피드백

### P2 — 제품 수준 추천
`ProductRecommendation`은 카탈로그, 변형, 출처, 개인정보 정책이 확정된 이후 별도 계약으로 진행한다.

P1 `RecommendationSession`에는 `Product`, `ProductVariant`, `price`, `availability`, `checkout`과 구매 흐름을 포함하지 않는다.

## 5. 핵심 사용자 시나리오

### 시나리오 A — 검색어 보정을 통한 매장 발견
사용자가 서울에서 주말 백패킹을 준비하며 `백패킨`을 검색한다. GearBy는 적용된 보정 내용을 공개하고 백패킹 매장을 지도와 목록에 동일하게 표시한다. 사용자는 상세 정보를 확인하고 NAVER 길찾기로 이동한다.

### 시나리오 B — 백패킹 입문 장비군 안내
사용자가 백패킹, 입문자, 1박, 봄, 대중교통, 가벼운 구성을 입력한다. GearBy는 숙박·수면·취사·보온·안전 장비군과 선정 이유를 제시하고, 누락된 필수 조건이나 무리한 경량화에 대한 경고를 표시한다.

### 시나리오 C — 검증된 매장 연결
사용자가 가이드 결과의 수면 장비군을 선택한다. GearBy는 해당 장비군 취급 근거가 검증되고 만료되지 않은 매장만 보여준다. 실시간 재고 보유를 주장하지 않는다.

## 6. 성공 기준

| 목표 | 지표 예시 |
| --- | --- |
| 매장 탐색 성공 | 검색·필터 후 상세 진입률, 길찾기·전화 전환율 |
| 정보 신뢰성 | 검증 유효 매장 비율, 만료 정보 비율, 정정 처리시간 |
| 가이드 완주 | 프로필 입력 완료율, 가이드 결과 조회율 |
| 가이드 유용성 | helpful 응답률, 경고·미충족 제약 확인률 |
| 두 축 연결 | 가이드 결과에서 검증 매장 탐색으로 이동한 비율 |

초기 목표치는 실제 운영 데이터 수집 후 확정한다. 근거 없이 수치를 약속하지 않는다.

## 7. 비기능 요구사항

- 기본 언어와 사용자 노출 용어는 한국어다.
- 모바일 웹과 데스크톱 웹을 지원한다.
- 관리자 기능은 데스크톱 웹을 우선한다.
- 지도 없이도 목록으로 동일한 핵심 정보를 탐색할 수 있어야 한다.
- 추천 결과는 동일한 입력과 규칙 버전에서 결정적이어야 한다.
- 규칙 버전은 API 계약과 운영 추적에 사용하며 일반 사용자 화면에는 노출하지 않는다.
- 매장 능력 근거에는 출처, 검증 시각, 만료 시각, 검증 상태가 있어야 한다.
- 오류 응답은 공통 `ApiResponse` 형식을 사용한다.

## 8. 제외 범위

- 실시간 가격·재고 보장
- 상품 구매, 결제, 대여, 예약
- 설명 없는 불투명 추천 순위
- 사용자 동의 없는 민감정보 수집
- 운영자 검수 없는 매장 취급 능력 주장

## 9. 주요 리스크

| 리스크 | 대응 |
| --- | --- |
| 초기 전국 매장 데이터 부족 | 전국 서비스 경계는 유지하되 지역별 수집률을 측정하고 검수된 데이터부터 순차 공개 |
| 외부 수집 정책·품질 불확실 | 공급자 약관·호출 범위·중복 제거·갱신 주기를 PoC로 검증한 뒤 채널별 사용 여부 확정 |
| 오래된 매장 정보 | 검증·만료 상태와 정정 흐름 운영 |
| 잘못된 검색어 보정 | 원문과 적용 검색어를 공개하고 운영자가 룰을 검수 |
| 과도한 추천 확신 | 장비군 수준 안내, 설명·경고·미충족 제약 제공 |
| P1의 상거래 범위 확장 | 제품·가격·재고·결제 필드를 계약에서 금지 |
