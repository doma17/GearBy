## 1. 공통 규칙

- 공개 기능은 모바일·데스크톱 웹에서 제공한다.
- 관리자 기능은 데스크톱 웹을 우선하며 인증된 `ADMIN` 세션에서만 진입점과 화면을 표시한다.
- 공개 매장 검색에는 `PUBLISHED` 상태의 매장만 포함한다.
- 지도와 목록은 같은 검색·필터 조건과 매장 집합을 사용한다.
- 모든 REST 응답은 `success`, `timestamp`, `data`, `error`를 가진 `ApiResponse` 계열 envelope를 사용한다.
- 한국 사용자에게 노출되는 설명, 오류, 경고는 한국어를 기본값으로 한다.

## 2. P0 지도 기반 매장 큐레이션

### CUR-F01 지도·목록 탐색

**입력**
- 카테고리: 등산, 백패킹, 캠핑, 클라이밍
- 검색어
- 지도 영역 또는 현재 위치
- 정렬: 이름순 또는 거리순

**동작**
- 복수 카테고리 선택을 지원한다. 선택한 카테고리의 결합 규칙은 추가 명확화가 필요하다.
- 필터 변경 시 지도 마커와 목록을 같은 결과로 갱신한다.
- 위치 권한이 없으면 거리순을 강제하지 않고 이름순 탐색을 제공한다.
- 지도 사용이 어려운 사용자를 위해 목록에서 동일 매장에 접근할 수 있게 한다.

**결과**
- 매장 ID, 이름, 주소, 좌표, 카테고리와 공개 가능한 기본 정보
- 커서 기반 다음 페이지 정보
- 원 검색어, 적용 검색어, 보정 결과

### CUR-F02 검색어 보정

- 카테고리명, 대표 동의어, 운영자가 승인한 매장명 보정 룰만 사용한다.
- 보정이 적용되면 원 검색어와 적용 검색어를 함께 공개한다.
- 보정 결과가 없거나 불확실하면 원 검색어로 검색하며 임의 결과를 만들지 않는다.
- 운영자는 보정 룰을 조회·등록·수정·비활성화할 수 있다.
- Elastic Stack 또는 Graph DB 기반 검색 확장은 현재 계약에 포함하지 않고 별도 PoC에서 정확도, 운영비용, 한국어 검색 품질을 검증한다.

### CUR-F03 매장 상세와 외부 연결

- 공개 상세에는 이름, 주소, 좌표, 카테고리, 전화번호, 영업시간, 소개를 표시한다.
- 전화번호가 있으면 모바일에서는 전화 연결, 데스크톱에서는 복사 가능한 번호를 제공한다.
- 길찾기는 매장 좌표와 이름을 사용해 NAVER 지도 외부 경로로 연결한다.
- 제공되지 않은 영업시간이나 전화번호를 추정하지 않는다.

### CUR-F04 정정·신규 매장 피드백

- 사용자는 `CORRECTION`, `GENERAL`, `NEW_STORE` 유형으로 피드백을 제출할 수 있다.
- 내용은 필수이며 연락처는 선택이다.
- 회신 이메일을 사용할 때는 연락 동의를 함께 받아야 한다.
- 접수 후 사용자에게 접수 ID와 상태를 반환한다.
- 운영자는 피드백을 검토하고 해결·반려 상태와 처리 요약을 기록한다.

### CUR-F05 매장 수명주기

매장 상태는 다음 순서를 따른다.

`DRAFT → IN_REVIEW → PUBLISHED`

- 검수 실패 시 `REJECTED`로 이동하고 수정 후 다시 검수할 수 있다.
- 공개 API에는 `PUBLISHED`만 노출한다.
- 신규 등록과 수정은 검수 완료 전 공개 데이터에 반영하지 않는다.
- 카테고리 오류 가능성은 검수 플래그로 관리한다.

### CUR-F06 관리자 운영

관리자는 다음 기능을 사용한다.

- 상태별 매장 조회, 생성, 수정, 검수, 공개, 반려
- 검색어 보정 룰 관리
- 피드백 조회와 처리
- 카테고리별 공개 매장 수와 수명주기 현황 조회
- 분류 검수 플래그 생성, 담당자 지정, 해결

관리 API는 인증된 `ADMIN` 권한만 허용한다.
- 인증되지 않았거나 `ADMIN` 권한이 없는 사용자는 관리자 진입점과 운영 데이터를 볼 수 없다.
- 직접 관리자 URL이나 API에 접근해도 각각 로그인·접근 거부 화면 또는 `401`·`403` 응답으로 차단한다.
- 실제 OIDC 공급자와 프런트엔드 세션 연동은 P0 출시 전 추가 검증한다.

### CUR-F07 외부 매장 후보 수집

- 대한민국 전역을 대상으로 크롤링과 NAVER 지도·검색 관련 API를 후보 수집 채널로 검토한다.
- 공급자별 약관, 저장·재사용 허용 범위, 호출 제한과 데이터 품질을 PoC에서 검증한 채널만 사용한다.
- 배치 작업은 출처, 수집 시각, 원본 식별자와 원본 URL을 함께 저장하고 주소·좌표·전화번호 등을 기준으로 중복 후보를 식별한다.
- 수집한 후보는 `DRAFT`로 저장하며 자동으로 `PUBLISHED`하지 않는다.
- 관리자가 중복과 핵심 정보를 확인하고 기존 수명주기를 통과시킨 매장만 공개 API로 제공한다.

## 3. P1 planned 활동·프로필 기반 장비군 가이드

### REC-F01 RecommendationSession 생성

- `POST /recommendation-sessions`로 세션을 생성한다.
- 초기 결과는 `id`와 `CREATED` 상태를 반환한다.
- 세션은 제품·가격·재고·구매 정보를 포함하지 않는다.

### REC-F02 프로필 입력

`PUT /recommendation-sessions/{sessionId}/profile`은 다음 값을 받는다.

| 필드 | 규칙 |
| --- | --- |
| activity | 활동을 표현하는 검증 가능한 문자열 |
| experienceLevel | 경험 수준을 표현하는 검증 가능한 문자열 |
| tripDuration | 활동 기간을 표현하는 검증 가능한 문자열 |
| season | 계절·기후 맥락을 표현하는 검증 가능한 문자열 |
| partySize | 1 이상의 인원수 |
| transport | 도보, 대중교통, 차량 등을 포함할 수 있는 검증 가능한 문자열 |
| preferences | 예산, 중량, 편의, 내구성 등의 선호 목록 |
| constraints | 반드시 만족하거나 제외할 조건 목록 |
| additionalContext | 기존 필드로 표현하지 못한 추가 요소의 키-값 집합 |

필수값이 누락되거나 범위를 벗어나면 `INVALID_REQUEST`를 반환한다.

### REC-F03 장비군 가이드

`GET /recommendation-sessions/{sessionId}/guidance`는 다음을 반환한다.

- `ruleVersion`: 결과를 생성한 규칙 버전. API 소비자와 운영 추적용이며 일반 사용자 UI에는 표시하지 않는다.
- `gearGroups`: 추상 장비군과 스타터 키트 여부
- `explanations`: 입력과 규칙에 근거한 선정 이유
- `warnings`: 안전, 계절, 경험 수준, 무리한 경량화 관련 주의
- `unmetConstraints`: 현재 규칙으로 충족하지 못한 조건

동일 입력과 동일 규칙 버전의 결과는 결정적이어야 한다. 근거가 부족하면 빈 결과와 이유를 반환하며 임의 추천을 만들지 않는다.

### REC-F04 검증 매장 연결

`GET /recommendation-sessions/{sessionId}/store-matches`는 장비군별 매장 연결을 반환한다.

각 연결에는 다음 근거가 필수다.

- `storeId`
- `gearGroup`
- `sourceType`
- `sourceUrl`
- `verifiedAt`
- `expiresAt`
- `verificationStatus=VERIFIED`

만료되었거나 검증되지 않은 근거는 공개 결과에서 제외한다. 이 결과는 취급 가능성의 근거이며 실시간 재고 보장이 아니다.

### REC-F05 추천 피드백

- `POST /recommendation-sessions/{sessionId}/feedback`은 `helpful`과 선택적 `reason`을 받는다.
- 접수 결과는 `ACCEPTED` 상태를 반환한다.
- 피드백은 향후 규칙 개선 자료로 사용하지만 P1에서 개인별 모델 학습을 수행하지 않는다.

## 4. 오류와 상태 처리

| 상황 | 결과 |
| --- | --- |
| 필수 입력 누락·잘못된 값 | 400 / `INVALID_REQUEST` |
| 존재하지 않는 매장·세션 | 404 / `NOT_FOUND` |
| 관리자 미인증 | 401 / `UNAUTHORIZED` |
| 관리자 권한 부족 | 403 / `FORBIDDEN` |
| 상태 전이 충돌 | 409 / `CONFLICT` |
| 내부 처리 실패 | 500 / `INTERNAL_ERROR` |

- 지도, 검색, 가이드, 매장 연결에는 명시적인 로딩·빈 결과·오류 상태가 있어야 한다.
- 오류가 발생했을 때 이전의 유효한 사용자 입력을 불필요하게 삭제하지 않는다.

## 5. 비기능 및 접근성

- 지도 조작 없이 검색, 목록, 상세, 길찾기를 완료할 수 있어야 한다.
- 키보드로 주요 컨트롤과 목록 항목에 접근할 수 있어야 한다.
- 지도 마커 선택과 목록 선택은 같은 매장 상세 상태를 사용한다.
- 모바일에서 주요 행동은 터치 가능한 크기와 한국어 레이블을 제공한다.
- 외부 지도 이동임을 사용자에게 알린다.

## 6. P2 경계

다음 항목은 현재 기능 명세에 포함하지 않는다.

- 제품 및 제품 변형 카탈로그
- 가격 비교
- 실시간 재고·구매 가능 여부
- 장바구니, 결제, 주문
- 설명 없는 개인화 순위
